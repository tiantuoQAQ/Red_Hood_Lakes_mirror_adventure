## 0. 先读这一段（最重要）

这是一个**网页游戏**，所有贴图以 PNG 加载，由代码叠加、旋转、缩放。

三件事必须一开始就理解，否则整批素材都要重做：

1. **全角色适用同一套色相。** 不是"主角用一套、BOSS 用另一套"——**所有角色**（主角、队友、敌人、BOSS、NPC、立绘、UI）都只能用下面三个色相加黑白灰。没有任何例外。
2. **角色之间不靠颜色区分。** 颜色只有三种，且每个颜色有固定的语义（见 1.2）。区分角色靠**剪影、明度层级、纹样**（见 1.3）。
3. **完全原创。** 不要参考、不要复刻、不要使用任何现成游戏的素材。尤其不要用《东方冰之勇者记》或东方 Project 的任何角色形象、名字、配色。我们只参考它的**玩法机制**。

**关于参考视频**：多数图像模型无法解析长视频。请附 **3～5 张关键静帧截图**（主角、敌人、BOSS、光球、UI 各一张），不要附整段视频。

## 1. 色彩规范（硬性，一票否决）

### 1.1 三个色相 + 灰阶

| 颜色 | 色值 | 色相角 | 语义（固定，不可挪用） |
| --- | --- | --- | --- |
| 纯红 | `#FF0000` | 0° | **一切伤害与危险**：弹幕、敌人本体、BOSS 核心 |
| 青蓝 | `#00BAFF` | 196.2° | **玩家阵营**：主角、队友、友方 NPC |
| 黄绿 | `#82FF00` | 89.4° | **能量与中立**：勇气、擦弹、拾取物、机关、治疗 |
| 灰阶 | 任意 | 无 | 背景、场景、阴影、文字、UI 结构 |

判断标准（程序会逐像素跑脚本检查）：

1. 丢弃完全透明的像素；
2. 丢弃**色度**（最大通道值 − 最小通道值）小于 20/255 的像素——这些是中性灰，不占色相名额；
3. 剩余像素的色相必须落在 `0°` / `89.4°` / `196.2°` 三个中心各 **±12°** 内；
4. 越界像素占比必须 **< 1%**。

### 1.2 允许与禁止

**允许**

- 同一色相内部的明暗、饱和变化（深红、暗青、亮绿……）
- 与黑 / 白 / 灰混合得到的所有色阶
- **红 → 白** 的径向渐变（白色无色相，不破坏规则）
- 纯灰阴影、纯灰描边、纯灰高光

**关于"灰阶"的精确定义**：灰阶必须**中性**，即 R=G=B。

"看起来像灰但其实偏色"的颜色会带上色相，被判成第四种颜色。典型踩线案例：

| 颜色 | 实际色相 | 问题 |
| --- | --- | --- |
| `#222D39` | 211° | 偏蓝的深灰，比允许的青蓝（196°）偏出 15° |
| `#3A2A1A` | 30° | 偏暖的深灰，就是棕色 |
| `#2B2B33` | 240° | 偏紫的深灰，藏青 |

背景、阴影、UI 结构请用 `#0B0B0B` / `#141414` / `#222222` / `#2F2F2F` 这类**纯粹的中性灰**。

**禁止**

- ❌ **两个不同色相之间直接渐变**。绿→红会经过橙色（约 40°），那是第四个色相。
- ❌ 彩色描边、彩色外发光叠加在异色图形上。
- ❌ **环境色光**：紫色阴影、棕色阴影、青绿反射、暖色逆光——这是最常见的违规来源。
- ❌ **低饱和但有色相的颜色**：棕色（约 30°）、米色（45°）、卡其（60°）、藏青（240°）、藕荷（300°）。它们看着"像灰"，但会直接违规。
- ❌ 粉色、橙色、紫色、青色之外的任何混色。
- ❌ **给某个角色单独指定一个"新"颜色**（例如"这个角色用紫色"）——不允许。

**相邻图形的隔离**：两个不同色相的图形不要直接相邻，抗锯齿会在交界处混合出中间色相。必须相邻时，用 1～2px **纯灰描边**隔开。

### 1.3 多个角色怎么区分（关键）

颜色只有三种，所以角色辨识必须靠下面三样，按优先级排列：

1. **剪影**（最有效）：体型比例、轮廓特征、帽子/披风/角/武器/发型外轮廓。让角色在纯黑剪影下也能分辨。
2. **明度分层**：同一色相内，给每个角色指定一个**专属明度档**。例如三个友方角色都用青：
   - 角色 A：亮青（明度 70%，`#5FD4FF` 一带）
   - 角色 B：中青（明度 50%，`#00BAFF`）
   - 角色 C：深青（明度 30%，`#00739F` 一带）

   并排放也不会混。**请为每个角色在交付说明里写明"主色明度档"**。
3. **纹样**：几何肌理、条纹走向、描边粗细、边缘破碎/圆润的差别。

绝对不要做的：靠新增色相区分角色。

### 1.4 阵营辨识（比角色辨识更重要）

玩家在一屏密集弹幕中必须能瞬间分清"我 / 我的东西 / 要躲的东西"：

- **青 = 我**（主角任何形态都保留青蓝识别色）
- **红 = 会杀我的**
- **绿 = 我能利用的**

这条优先级高于角色个性。任何设计如果让"会杀我的东西"不是红色，就作废。

## 2. 通用交付规范

| 项目 | 要求 |
| --- | --- |
| 格式 | PNG-32（带 alpha），sRGB |
| 尺寸 | 文中给的是**最终使用尺寸**，请按 **2 倍**出图（需要 64×64 就给 128×128），下采样由程序完成 |
| 背景 | 透明。若无法输出透明，用纯白 `#FFFFFF` 背景，文件名后加 `_whitebg` |
| 边距 | 主体四周留 ≥8px（2 倍图）透明边距，**不要切边** |
| 内容 | 一张图只放一个主体，**不要拼多格 sprite sheet** |
| 文字 | 不要在图里画任何文字 |
| 阴影 | 不要把落地投影烘焙进图里（由代码绘制） |
| 视角 | 玩家与敌人统一**侧视、朝右** |

### 关于帧数：只要关键姿势，不要逐帧序列

跨帧一致性无法保证，而我们的动作用代码做位移、旋转、缩放、挤压拉伸，更顺滑也不会错位。

**每个动作只需 1 张关键姿势。** 唯一需要多张的是**立绘表情差分**（每人 3 张）。

### 锚点

| 类型 | 锚点 |
| --- | --- |
| 角色 / 敌人 | 脚底中心（画布底部中央，留 8px） |
| BOSS / 光球 / 子弹 | 几何中心 |
| 立绘 | 底部中心 |

## 6. 交付结构

```
art/
  char_hero_idle.png
  char_hero_ball.png
  char_<id>_idle.png
  boss_mirror_idle.png
  portrait_<id>_calm.png
  ui_life.png
  bg_lake.png
  manifest.json
```

`manifest.json`（把每个角色的阵营、主色明度档、剪影特征写清楚，方便程序与后续角色扩建）：

```json
{
  "char_hero": {
    "name": "主角",
    "camp": "player",
    "hue": "#00BAFF",
    "lightness": 0.60,
    "silhouette": "hooded cloak, slim, short cape",
    "scale": 0.5,
    "anchor": "bottom-center"
  },
  "char_hero_ball": { "anchor": "center", "scale": 0.5 },
  "boss_mirror_idle": { "anchor": "center", "scale": 0.5 }
}
```

`scale: 0.5` = 按 2 倍出图、程序下采样一半。
