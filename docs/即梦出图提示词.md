## 1. 先讲清楚：动画到底怎么做

2D 游戏里做角色动作，只有两条路：

| 做法 | 是什么 | 代价 |
| --- | --- | --- |
| **逐帧动画** | 每一帧一张图，连起来播 | 一个跑动循环就要 8–12 张，AI 出的帧之间还会抖、会变形，45 小时做不完 |
| **分件动画**（我们选这个） | 把角色切成几块，代码各自旋转、偏移、挤压，实时合成 | 只需几张大图，动作由代码算，改手感不用重画 |

所以你说的「把头和手拆下来」方向是对的，这就是业界做法（Spine、Live2D、DragonBones 都是这么干）。
**但零件不是越多越好**，尤其画是 AI 出的——零件越多，接缝越容易露、越对不齐。

### 我们给蕾克定的分件：4 件

| 文件 | 内容 | 层级 | 能做出什么 |
| --- | --- | --- | --- |
| `cape.png` | 斗篷后摆 | 最底 | 跑动时向后甩、冲刺时大幅滞后 |
| `hair.png` | 后发（不含刘海） | 次底 | 移动时延迟摆动 |
| `body.png` | 躯干 + 手臂 + 双腿 + 短靴 | 中 | 前倾、挤压拉伸 |
| `head.png` | 头 + 脸 + 兜帽 + 兽耳 + 刘海 + 眼镜 | 最上 | **点头、受击摇头、朝向前探** |

头单独拆出来的理由：兜帽把脖子接缝整个盖住了，拆了不会露缝，而且「头能自己动」是角色有没有生命感的关键。

### 为什么手不拆

- 手是 AI 最容易崩的部位（多指、畸形），单独出图崩得更厉害；
- 手一拆，手臂就要重画「被身体挡住的那一段」，遮挡顺序每帧都在变，调它至少多花 3–4 小时；
- 收益却很低——这个游戏里手在跑动和冲刺时几乎看不出来。

**如果后面真需要**，只做一件 `arm.png`：持枪的前臂 + 手，用在射击动作上，不拆手指。

## 2. 交付规格（每张都按这个来）

| 项目 | 要求 |
| --- | --- |
| 画布 | 竖图 3:4，最终统一 512×768（即梦出 1024×1536 也行，我缩） |
| 背景 | 纯白（我这边脚本抠透明），不要地面、阴影、文字、边框 |
| 站位 | **所有分件画布尺寸完全相同**，角色脚底线对齐画布底部中央 |
| 角度 | 侧视角，面朝画面右侧，整套统一，不许有的件正面有的件侧面 |
| 配色 | 只有红 `#FF0000` / 黄绿 `#82FF00` / 青蓝 `#00BAFF` + 中性灰（R=G=B） |
| 数量 | 一次出 4 张挑 1 张 |

> 分件对不齐不用重抽：游戏 `F2` 面板里有每层的 X/Y 微调滑块，拖到对上就行。

### 4.5「多个动作」怎么来（**不用即梦再出图**）

一套 4 件分件，代码就能合成整套动作：

| 动作 | 怎么合成 |
| --- | --- |
| 待机 | 整体上下浮动 2px + 呼吸缩放 1.00→1.015 + 头轻晃 + 后发/斗篷延迟摆动 |
| 跑动 | 整体前倾 4° + 浮动加快 + 上下起伏加速 |
| 冲刺 | 前倾 20° + 横向拉长 1.12 + 纵向压扁 0.92 + 残影 + 速度线 |
| 起跳 / 下落 | 纵向拉伸 1.04 |
| 受击 | 白色冲击环闪一下 + 角色抖动 2 帧 |
| 光球形态 | 单独一张圆球，整体旋转 + 呼吸缩放 |

**动作是算出来的，不是画出来的**——所以不需要「待机帧 / 跑动帧 / 冲刺帧」。
想改手感只调参数，不用重画，也不用回即梦。

> 如果你想要「冲刺瞬间切一张更帅的姿势图」（格斗游戏那种换帧），可以做，
> 但换帧那一刻比例会跳——除非两张的头身比、脚底线完全一致，而这正是 AI 最难保证的。
> 建议：**先用分件跑起来**，觉得不够帅再补姿态帧。

## 7. BOSS 出场动画：用视频，但有个坑要提前知道

思路没错——即梦/可灵出 3–5 秒的角色出场动作（比如从镜面里浮出、裙摆展开、抬手），
但**视频默认不透明**，直接贴进 canvas 会是一块矩形挡住背景。两种落地方式：

| 方案 | 做法 | 风险 |
| --- | --- | --- |
| **黑底 + 滤色叠加**（推荐） | 视频背景出成**纯黑**，canvas 里用 `globalCompositeOperation = 'screen'` 叠上去。我们画面本来就是深色底，青色角色在黑底上滤色后几乎看不出黑边 | 角色暗部会被背景提亮一点 |
| 抽帧成 PNG 序列 | 视频抠透明后抽成 24 帧 PNG，代码按帧播 | 文件大、要手动抠、内存高 |

**出视频时的提示词要点**：纯黑背景、单个角色、镜头固定、角色从左外侧移入画面中央、不要转场、不要文字、不加音效。
视频先放着，等静态图过关了再弄——静态图是地基。

## 8. 光球形态（**已经做完了，不用再出图**）

光球不是一张贴图，是代码实时画的：脉动球体（白心→红边径向渐变）+ 三条旋转青弧 + 冲击波环。
好处是永远清晰、不糊、能跟着帧率呼吸，而且换配色只改一行常量。

粒子拖尾用的是这张贴图：

| 文件 | 规格 | 说明 |
| --- | --- | --- |
| `art/fx/particle_strip.png` | 2048×256，8 帧横排（每帧 256×256），透明底 | 红swoosh + 白星点，运行时按存活进度切帧 |

> **注意**：原图里的星点是米色（色相 20°–40°），会让整张图色相越界 20.63%。
> 已经用 `tools/_fix_fx_palette.py` 把 2909 个暖色像素拉成中性白，现在 **越界 0.00% PASS**。
> 以后换粒子图都要先跑一遍 `python tools/check_palette.py art/fx/particle_strip.png`。

相关代码：`src/fx.js`（绘制）＋ `src/game.js`（粒子生成与推进，逻辑层，方便 node 测试）。
自检：`node test/fx_smoke.js`。

## 10. 验收清单（每张都要过）

- [ ] 只有目标那一块，没有多余的部件
- [ ] 侧视、面朝右（玛丽苏朝左），整套角度一致

- [ ] 涂成纯黑剪影能认出是谁
- [ ] 四件画布尺寸一致，脚底线在同一水平

## 11. 即梦常见翻车与补救

| 症状 | 原因 | 补救 |
| --- | --- | --- |
| 皮肤肉色 / 头发金色 | 模型默认画人 | 正向写死「皮肤接近白的浅灰」「头发中性灰」，反向保留「肤色、金色头发」 |
| 出成正面站姿 | 参考图是正面设定 | 正向开头保留「侧视角、面朝右」 |
| 分件里带出别的部件 | 模型按"整个人"理解 | 正向末尾单独一段写「不要画……」 |
| 四件比例对不上 | 模型每次构图不同 | 每件都写「角色高度占画面 80%」，对不上用 F2 滑块救 |
| 出现紫/粉/橙 | 渐变、彩色光晕 | 正向写「硬边平涂、不用渐变」，反向加「彩色光晕、彩色阴影」 |
| 照抄原图的蓝发/红裙 | 参考强度太高 | 降参考强度，正向开头先声明只用三色 |
