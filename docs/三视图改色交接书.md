# 三视图改色交接书 · 《镜》

> 收件方：图像处理方（GPT 或执行改色的人员/脚本）
> 输入：现成的角色三视图（正面 / 侧面 / 背面）
> 任务：**把现有三视图的配色改成指定色板**，不是重新绘制

---

## 0. 任务定义（先读，决定成败）

这是**改色任务**，不是生成任务。

你有现成的三视图，人物形象、比例、动作、服装细节、线条风格**全部已经定了**。你要做的只有一件事：**换颜色**。

### 三条红线

1. ❌ **不要重绘**。不要"优化"线稿、不要补细节、不要改比例、不要改姿势、不要改构图、不要加特效。
2. ❌ **不要改变角色的辨识特征**。发型轮廓、服饰剪裁、配饰位置、耳朵/尾巴/翅膀等一切外形信息必须原样保留。
3. ❌ **不要新增颜色**。改完之后，全图只能出现三种色相 + 黑白灰（见第 2 节）。

如果做不到"只改颜色"，请交给脚本处理（见第 6 节），而不是让图像模型自由发挥。

### 为什么这么严格

比赛规则限制：全画面**只能出现 3 个色相 + 灰阶**。这不是风格偏好，是硬性判定。多出任何一种颜色，作品就可能被判不符题。

## 1. 输入三视图的规格要求

| 项目 | 要求 |
| --- | --- |
| 视角 | 正面 / 侧面 / 背面 三视图齐全，同一画布或分成三张 |
| 背景 | 透明或纯白；若有复杂背景请先抠图 |
| 分辨率 | 每张不低于 1024px 高（改色后我会下采样） |
| 线稿 | 清晰可辨，描边与填充色能区分 |
| 一致性 | 三个视角必须是同一个角色、同一套服装 |

若三视图缺视角或线稿不清，**先告知，不要自行补画**。

## 2. 目标色板（硬性）

| 颜色 | 色值 | 色相角 | 语义 |
| --- | --- | --- | --- |
| 纯红 | `#FF0000` | 0° | **我方**：蕾克、友方角色、玩家的攻击与擦弹反馈 |
| 黄绿 | `#82FF00` | 89.4° | **危险**：一切弹幕、致命机关 |
| 青蓝 | `#00BAFF` | 196.2° | **环境与中立**：镜面、冰、湖、反射、中立角色 |
| 中性灰 | R=G=B | 无 | 结构、背景、UI、文字 |

> 红色给了主角（小红帽的符号意义优先），所以"会杀死玩家的东西"改用绿色。绿色是三个色里最亮的，在深色背景上辨识度最高。**弹幕一律是绿的。**

### 中性灰的精确定义

灰阶必须**中性**（R=G=B）。"看着像灰但偏色"的颜色会带上色相，被判成第四种颜色：

| 踩线颜色 | 实际色相 | 问题 |
| --- | --- | --- |
| `#222D39` | 211° | 偏蓝深灰，比允许的青蓝偏出 15° |
| `#3A2A1A` | 30° | 偏暖深灰，就是棕色 |
| `#2B2B33` | 240° | 偏紫深灰，藏青 |

皮肤、金属、皮革这类"看起来中性"的地方最容易踩雷：**肤色（红橙系）、皮革（棕色）、金色（黄橙系）全部违规**。统一按第 4 节的规则处理。

## 3. 角色色相分配表

### 3.1 分配原则

- **阵营优先于角色个性**：红=会伤到玩家的，青=玩家阵营，绿=中立/可交互，灰=非战斗或特殊。
- **同色相内用明度分层区分角色**：每人一个专属明度档，并排也不会混。
- **剪影负责辨识，颜色负责语义**。这是三色限制下唯一可行的做法。

### 3.3 三个需要说明的决定

**① 小红帽是红的，"危险"因此改成绿色。**
红的符号意义归主角。弹幕必须用绝不属于玩家的颜色，否则玩家在密集弹幕里找不到自己。绿色被选中是因为它是三个色里最亮的，深色背景上辨识度最高。代价是绿色在游戏惯例里常代表"安全"，所以**弹幕必须用锐利的几何形状**，不能画得圆润可爱。

**② 蕾克有三套配色，共用同一份线稿。**
红（战斗常规）、青（剧情·被影响）、红·暗档（猩红魔姬）。三套**形状像素级一致**，只有配色不同。用脚本对同一份三视图跑三次即可，不要分别重绘。

**③ `rek_crimson` 与 `rek` 同剪影、暗一档。**
叙事上"她一直是你，只是暗了一档"。所以不许给她加角、加翅膀、改比例——只许调明度。

> 若你希望改成别的分配，请先说——整条语义链牵一发动全身，不能只改一个人。

## 4. 改色规则（两种方案，按三视图复杂度选）

### 方案 A：整图单色相重映射（推荐，适用于线稿 + 平涂风格）

把整张图映射到角色的目标色相，**保留原有的明暗结构**：

对每个像素：

1. 取原像素的**相对亮度** `L_src`（把 RGB 转灰度后归一化到 0~1）；
2. 把 `L_src` 映射到角色的明度区间：`L_out = L_min + (L_max - L_min) × L_src`；
3. 色相固定为角色的目标色相 `H`；
4. 饱和度：原图饱和度高的地方保持较高（`S_out ≈ 0.85`），接近线稿的地方压低到 0（线稿变纯黑/深灰）；
5. 原图中**本来就接近中性**的像素（色度极低，如纯黑描边、白色高光）保持中性，不要染色。

效果：整张图变成"目标色相的明暗画"，形状完全不变。

**示例映射（蕾克，青，L 0.58 档，方案 A）**

| 原图区域 | 原色（示意） | 改后 |
| --- | --- | --- |
| 红兜帽 | `#C0392B` | 青，高明度 `#6FD3FF` 一带 |
| 红兜帽暗部 | `#7B241C` | 青，低明度 `#0A5B85` 一带 |
| 肤色脸 | `#F2C9A0` | 青的浅档 `#9FDFFF` 一带（见下方说明） |
| 深棕靴子 | `#4A3020` | 青的暗档 `#0A4A6B` 一带 |
| 黑色描边 | `#1A1A1A` | 保持中性黑 |

> **说明**：方案 A 会把**所有有彩色的区域**统一映射到目标色相，包括皮肤和皮革——它们不再是肤色和棕色。这是刻意的：肤色和棕色都会带进第四、第五个色相。
>
> 如果希望"皮肤保持中性灰、服装才是青色"，那就必须走方案 B（分层），把皮肤单独分出来做灰阶。方案 A 做不到，不要为了让它做到而牺牲形状。

### 方案 B：分层重映射（适用于色块多、材质丰富的三视图）

先把三视图按**语义**拆成 3~5 个色块层，再对每层套不同的目标色阶：

| 语义层 | 目标 |
| --- | --- |
| 主服装 | 目标色相的中高明度（角色专属档） |
| 皮肤 | 中性浅灰（`#D0D0D0` ~ `#EFEFEF`） |
| 金属 / 兵器 | 中性灰（`#808080` ~ `#C0C0C0`），可加白色高光 |
| 布料内衬 / 阴影 | 目标色相的暗档，或中性深灰 |
| 描边 | 纯黑或中性深灰 |

方案 B 质量更高但需要分层。若图像模型无法可靠分层，**退回方案 A**，不要硬做。

### 实测结论（2026-10-23，用蕾克的设定稿跑过）

| 指标 | 方案 A（整体单色化） | 方案 B（分层，皮肤与头发转灰） |
| --- | --- | --- |
| 形状是否改变 | 否，逐像素一致 | 否，逐像素一致 |
| alpha 通道 | 与原图完全相同 | 与原图完全相同 |
| 明暗层级（Spearman） | 0.9945 | 0.9945 |
| 色相越界 | 0.00% | 0.00% |
| 皮肤表现 | **变成红色 / 蓝色，像外星人** | 中性灰，符合规则 |
| 是否可用 | 游戏内小尺寸可用，立绘不可用 | 可用 |

**结论：立绘和设定图必须走方案 B；游戏内 40px 的精灵图两者差别不大。**

方案 B 的一个便宜实现（不需要手工分层）：**按源图的色相窗口分区**。
皮肤与金发通常落在 12°～62° 之间，把这部分像素强制转成中性灰，其余区域吃目标色相：

```bash
python tools/recolor.py 三视图.png -o out/rek_red.png \
    --hue 0 --lightness 0.30 0.86 --neutral-hues 12,62
```

**已知局限**：这个窗口会把金发也一起变灰。如果希望头发保留层次，需要真正的图层级分层（由图像模型按语义分区），而不是靠色相窗口猜。

### 皮肤提亮（折中方案，已实测）

纯中性灰的皮肤在设定稿上会显得"失去血色"。把这一层**整体提亮到高明度带**能解决观感问题，且仍然不引入色相：

```bash
python tools/recolor.py 三视图.png -o out/rek_red.png \
    --hue 0 --lightness 0.30 0.86 --neutral-hues 12,62 --neutral-lightness 0.80,0.94
```

三档实测对比：

| 皮肤明度带 | 观感 | 与白底的关系 |
| --- | --- | --- |
| 保持原亮度（不传该参数） | 灰皮，像怪物 | 正常 |
| **0.80 – 0.94（推荐）** | **接近白皙皮肤，明暗层次保留** | 正常，边缘清晰 |
| 0.88 – 0.98 | 过曝、发白发平 | **开始和白底糊在一起**，边缘模糊 |

**推荐值 `0.80,0.94`。** 再往上提会损失立体感，并和白色背景混在一起——设定稿都是白底，这一点很关键。

## 6. 更可靠的做法：用脚本改（推荐）

改色是**确定性任务**，扩散模型做这件事天生不可靠：它会重画细节、改变线条、颜色也不精确。

程序侧已经提供了脚本 `tools/recolor.py`：

```bash
python tools/recolor.py 三视图.png -o 输出目录 \
    --hue 196.2 --lightness 0.40 0.75 --id rek
```

它做的正是方案 A：保留明暗结构，只替换色相，形状像素级不动。改完可以直接跑色板检查：

```bash
python tools/check_palette.py 输出目录
```

**建议分工**：GPT 负责三视图本身的绘制/补全；改色交给脚本，结果可复现、可批量、可验收。

## 7. 验收清单

- [ ] 与原始三视图逐像素比对，**轮廓与细节完全一致**（没有重画痕迹）
- [ ] 全图只有三种色相 + 中性灰，没有肤色、棕色皮革、金色饰品残留
- [ ] 灰阶部分 R=G=B，没有偏蓝/偏暖的"深灰"
- [ ] 三个视角颜色一致
- [ ] 同色相内不同角色的明度档能区分（把 `rek`、`norden`、`mermaid` 并排看）
- [ ] `check_palette.py` 越界像素 < 1%

## 8. 一句话总结

**保留一切形状，只换颜色；只有三种色相加中性灰；同色相靠明度分档区分角色；拿不准就用脚本。**
