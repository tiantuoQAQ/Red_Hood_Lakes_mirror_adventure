# 《镜》冲刺流光特效方案

> G1 设计文档。本文只定义表现层，不修改网页端或 Godot 端代码。逻辑基准为固定 60 Hz：冲刺速度 1020 px/s、位移 12 帧、无敌 16 帧、起步 3 帧加速、结束滑行 6 帧；现有网页端每 2 帧记录一次残影。

## 1. 目标与总原则

冲刺要让玩家读到三个阶段：起步发力、满速穿行、结束滑行。画面中心仍由角色和判定点承担，流光只强化方向与速度，不遮挡危险弹幕。所有冲刺图层均在世界空间绘制，屏幕层最后在 HUD 前绘制。

推荐绘制顺序（由后至前）：

1. 屏幕层（仅边缘/方向性反馈，不盖住中心判定点）
2. 速度线层
3. 拖尾层
4. 残影层
5. 玩家本体与白色判定点
6. 光点层（世界空间粒子，可在本体前后分两次画）

若实现需要严格的后处理顺序，可将屏幕层放在所有世界层之后、HUD 之前；光点层的后半段放在玩家本体之后。

## 2. 分层拆解

### 2.1 残影层

- **画法**：每 2 帧采样一次玩家中心 `(x, y)`，画一个沿朝向旋转 45° 的红色菱形/角色剪影；不使用纹理渐变。冲刺中采样点寿命 12 帧，结束滑行采样点寿命 8 帧。
- **参数**：尺寸 `visualR * 1.10 = 22 px`；冲刺中 alpha `0.28 * life / maxLife`；结束滑行同曲线但最大 alpha `0.20`；最多保留 9 个点（12 帧冲刺约 6 点，加滑行约 3 点）。
- **混合模式**：`source-over`。红色残影需要保持实体轮廓，避免 additive 叠到白色后变成无法区分的亮斑。
- **生命周期**：冲刺残影 12 帧；滑行残影 8 帧；每 2 帧生成 1 个。

### 2.2 速度线层

- **画法**：从玩家当前位置沿速度反方向画 2~3 条短线，线段终点落在玩家后方；起步阶段线长随速度比例增长，满速时达到最大，滑行阶段随速度衰减。线段两端使用圆帽，避免锯齿断裂。
- **参数**：每帧 2 条（低配 1 条）；线长 `18 + 54 * speedRatio` px，最大 72 px；线宽 2.0 px（起步）至 3.5 px（满速）；横向偏移 `[-7, 7]` px；每条寿命 3 帧；alpha 曲线 `0.62 * (1 - age / 3)^0.75`。
- **混合模式**：`lighter`/Godot `ADD`。只画白色或红色单色线，不在线条内部叠加半透明红白渐变。
- **生命周期**：每条 3 帧；冲刺 12 帧加滑行 6 帧，最多同时约 6 条，峰值不超过 8 条。

### 2.3 光点层

- **画法**：冲刺起步和结束各有小型点状火花；起步 burst 只在触发帧生成，点沿冲刺方向的侧后方散开。普通冲刺使用红色，起步中心可叠 1 个白点作为发力读数。
- **参数**：起步 8 颗（与网页端 `burst(..., 8)` 对齐）；每颗初速度 40~130 px/s，半径 1.5~3 px，寿命 10~16 帧；每帧常规补 1 颗，低配关闭常规补点；点 alpha `1 - age / life`，半径 `r * (1 - 0.45 * age / life)`。
- **混合模式**：`lighter`/`ADD`；红点和白点分批绘制，白点最多占 1/8，避免中心形成粉色大片。
- **生命周期**：起步点 10~16 帧；滑行补点 6~10 帧；全程粒子预算计入统一上限。

### 2.4 拖尾层

- **画法**：沿冲刺速度反方向铺一条窄的红色带状拖尾，使用 3 个离散宽度采样点，不使用连续彩色渐变。带尾部拆成 2~3 个红色透明线段，长度随速度比例变化。
- **参数**：最大总长 96 px；近身宽 8 px、尾端宽 2 px；每帧 1 条（从速度线层共享采样，避免重复对象）；alpha 从 `0.34` 线性降到 `0`；冲刺满速时长度 96 px，起步按 `0.45 + 0.55 * eased` 缩放，滑行按当前速度比例缩放。
- **混合模式**：`lighter`/`ADD`，但每个采样段只使用 `#FF0000`；禁止红色与白色在同一像素重复高强度叠加。
- **生命周期**：单条 4 帧；冲刺和滑行均每 2 帧更新一次；同时存在不超过 3 条。

### 2.5 屏幕层

- **画法**：仅在屏幕边缘画一条沿冲刺方向移动的细白色速度晕线，中心区域保持透明；不做全屏红闪，不给弹幕染色。可选地在冲刺触发后的第 0~2 帧做极轻的边缘亮度提升。
- **参数**：持续 4 帧；边缘最大 alpha 0.10；内边距 64 px；晕线宽度 2 px；沿冲刺方向的屏幕位移 8 px/帧；第 0 帧 `0.10`，第 1 帧 `0.075`，第 2 帧 `0.045`，第 3 帧 `0.015`，第 4 帧归零。
- **混合模式**：`lighter`/`ADD` 仅对白色边缘线使用；若引擎后处理不稳定，退回 `source-over` 的白色低 alpha。不得使用红色半透明覆盖背景和黄绿色弹幕。
- **生命周期**：触发后 4 帧；每次普通冲刺最多触发 1 次。低配直接关闭。

## 3. 参数表（60 Hz，可直接抄入代码）

| 参数 | 数值 | 用途 |
| --- | ---: | --- |
| `dashSpeed` | `1020 px/s` | 冲刺目标速度 |
| `dashFrames` | `12` | 满速位移帧数 |
| `dashIFrames` | `16` | 无敌帧，不改变特效寿命 |
| `dashRampFrames` | `3` | 45% 到 100% 的起步帧数 |
| `dashOutFrames` | `6` | 结束滑行帧数 |
| `dashOutKeep` | `0.72` | 滑行每帧保留速度比例 |
| `trailSampleEvery` | `2 帧` | 残影/拖尾采样间隔 |
| `ghostLife` | `12 帧` | 冲刺残影寿命 |
| `ghostOutLife` | `8 帧` | 滑行残影寿命 |
| `ghostMax` | `9` | 残影同时存在上限 |
| `speedLinePerFrame` | `2` | 速度线每帧新增数量，低配为 1 |
| `speedLineLife` | `3 帧` | 速度线寿命 |
| `speedLineWidth` | `2.0~3.5 px` | 按速度比例插值 |
| `speedLineLength` | `18~72 px` | 按速度比例插值 |
| `trailLength` | `96 px` | 满速拖尾长度 |
| `trailWidth` | `8 -> 2 px` | 近身到尾端宽度 |
| `trailAlpha` | `0.34 -> 0` | 拖尾 alpha 曲线 |
| `burstCount` | `8` | 普通冲刺起步光点 |
| `lightDotPerFrame` | `1` | 常规光点新增数量 |
| `lightDotLife` | `10~16 帧` | 起步光点寿命 |
| `screenLife` | `4 帧` | 屏幕层寿命 |
| `screenAlpha` | `0.10, 0.075, 0.045, 0.015` | 逐帧 alpha |
| `dashParticleBudget` | `32` | 单次冲刺特效粒子预算 |
| `particleMax` | `260` | 与网页端 `Game.particles` 上限对齐 |

建议统一使用 `speedRatio = clamp(abs(vx) / 1020, 0, 1)`。起步速度按现有 ease-out：`k = 1 - dashRampT / 3`，`speedRatio = 0.45 + 0.55 * (1 - (1-k)^2)`。

## 4. 三色合规与叠加规则

本方案允许的彩色只有：红 `#FF0000`、青蓝 `#00BAFF`、白（中性灰阶），另加中性灰背景。冲刺特效默认只用红和白；青蓝保留给镜面/环境，不作为冲刺主体色。黄绿 `#82FF00` 是危险弹幕专属，不进入任何冲刺层。

- **颜色分配**：残影、拖尾、普通光点用红；速度线以白为主、最多一条红线作方向强调；屏幕层只用白；背景和暗部只用中性灰。
- **叠加顺序**：先屏幕后方背景，再速度线与拖尾，再残影，再角色本体和白色判定点，最后少量光点；屏幕白线在 HUD 前、玩家中心外缘完成。
- **混合原因**：`lighter`/`ADD` 只对同一色相或白色单色几何体做加亮，不做红色 alpha 与白色 alpha 的连续混合渐变；因此只会改变明度，不引入新的色相。红层与白层若重叠，白色通道提升后视觉上仍按白/红两种允许色读取。
- **禁止项**：禁止红色屏幕蒙版覆盖黄绿弹幕（会产生橙色）；禁止红+青同像素渐变（会产生紫/洋红）；禁止使用非中性深蓝灰；禁止把黄绿用于玩家冲刺。

## 5. Canvas 2D 伪代码

```js
const DASH_FX = {
  ghostLife: 12, ghostOutLife: 8, sampleEvery: 2,
  linePerFrame: 2, lineLife: 3,
  burst: 8, dotPerFrame: 1,
  maxParticles: 260, maxDashParticles: 32,
  screenLife: 4
};

function startDashFx(p) {
  p.dashFx = { screenT: DASH_FX.screenLife, dots: 0 };
  burst(p.x, p.y, '#FF0000', DASH_FX.burst);
}

function updateDashFx(p, frame) {
  const active = p.dashT > 0 || p.dashOut > 0;
  if (!active) return;
  const speedRatio = clamp(Math.abs(p.vx) / 1020, 0, 1);
  const back = p.facing < 0 ? 0 : Math.PI;
  if (frame % 2 === 0) {
    p.trail.push({ x: p.x, y: p.y, life: p.dashT > 0 ? 12 : 8,
      max: p.dashT > 0 ? 12 : 8, facing: p.facing });
    spawnDashTrail(p.x, p.y, back, speedRatio, 1);
  }
  for (let i = 0; i < (lowSpec ? 1 : 2); i++)
    spawnSpeedLine(p.x, p.y, back, speedRatio, 3);
  if (!lowSpec && frame % 2 === 0 && dashParticleCount < 32)
    spawnDot(p.x, p.y, back, 10 + Math.random() * 6);
  if (p.dashFx && p.dashFx.screenT > 0) p.dashFx.screenT--;
}

function drawDashFx(ctx, p) {
  drawSpeedLines(ctx, p, 'lighter', '#FFFFFF');
  drawDashTrail(ctx, p, 'lighter', '#FF0000');
  drawGhosts(ctx, p, 'source-over', '#FF0000', t => 0.28 * t.life / t.max);
  drawPlayer(ctx, p); // 本体与白色判定点
  drawDashDots(ctx, 'lighter');
}

function drawDashScreen(ctx, fx) {
  if (!fx || fx.screenT <= 0) return;
  const a = [0.10, 0.075, 0.045, 0.015][4 - fx.screenT] || 0;
  ctx.save();
  ctx.globalCompositeOperation = 'lighter';
  ctx.strokeStyle = `rgba(255,255,255,${a})`;
  drawEdgeSpeedLine(ctx, fx.direction, 64, 2);
  ctx.restore();
}
```

伪代码中的 `spawn*` 应先检查全局粒子数和本次冲刺计数；满载时优先保留残影，依次丢弃光点、速度线、屏幕层。所有 `save()` 后必须恢复混合模式和 alpha，避免污染 HUD。

## 6. Godot 4 建议

### 6.1 `_draw()` 图元方案（推荐基线）

在玩家或独立 `Node2D` 的 `_draw()` 中按本方案顺序调用 `draw_line()`、`draw_polyline()`、`draw_circle()`。冲刺残影使用预计算的红色菱形点列；速度线和拖尾直接按 `Vector2(-sign(vx), -sign(vy))` 延伸。每帧 `_physics_process()` 更新 60 Hz 状态，随后 `queue_redraw()`。

用 `CanvasItemMaterial` 的 `blend_mode = BLEND_MODE_ADD` 给速度线、拖尾和光点节点；残影用默认 `BLEND_MODE_MIX`。白色屏幕层放在 `CanvasLayer` 的低层级，避免盖住 HUD 文本。不要在 `_draw()` 内创建对象或纹理，数组在初始化时复用。

```gdscript
func _draw() -> void:
    draw_speed_lines(Color.WHITE, 2.0, 72.0)
    draw_dash_trail(Color("ff0000"), 96.0, 8.0, 2.0)
    draw_ghosts(Color("ff0000")) # alpha = 0.28 * life / max_life
    draw_player_body()
    draw_dash_dots()
```

### 6.2 `GPUParticles2D` 方案

光点层适合 `GPUParticles2D`：`amount = 32`（单次冲刺预算），`lifetime = 0.20~0.27 s`（12~16 帧），`randomness = 0.35`，初速度 `40~130`，方向为速度反向，`scale_amount` 对应 1.5~3 px。粒子材质使用 `CanvasItemMaterial.blend_mode = BLEND_MODE_ADD`，粒子纹理只准红/白/中性灰。

残影和速度线不建议完全交给粒子系统：残影需要精确采样玩家位置，速度线需要根据实际速度动态改变长度。两者用 `_draw()` 数组维护更容易与网页版逐帧对齐。满屏弹幕时将 `amount` 降为 16，或暂停常规光点发射，仅保留起步 burst 的前 4 颗。

## 7. 性能预算与低配降级

- **满屏弹幕预算**：每帧冲刺特效新增最多 4 个对象：2 条速度线、1 个拖尾采样、1 个光点；每 2 帧额外更新 1 个残影采样。起步 burst 8 颗一次性计入预算，不重复发射。
- **总量上限**：所有通用粒子不超过 260；单次冲刺特效不超过 32；残影 9、速度线 8、拖尾 3 分别是固定小数组，不申请临时对象。超限时按“残影 > 拖尾 > 速度线 > 光点 > 屏幕线”保留。
- **更新方式**：固定 60 Hz；数组倒序删除过期项；Godot 使用对象池/固定数组，Canvas 使用复用记录。禁止每帧生成渐变纹理、Canvas 离屏大图或新的 `Image`。
- **低配一级**：速度线 2 条降为 1 条，光点每 2 帧 1 颗，GPUParticles amount 16；残影和拖尾保留。
- **低配二级**：关闭屏幕层，关闭常规光点，只保留 8 颗起步 burst、残影和一条拖尾；总新增不超过每帧 2 个。
- **极限模式**：只画残影（每 3 帧采样、最多 6 个），不画速度线/光点/屏幕层；冲刺逻辑和无敌帧不变。

## 8. 验收

1. **起步读数**：触发冲刺后第 3 帧内，画面至少出现 2~3 段位置递进的红色残影；速度线长度从约 38 px 递进至 72 px，且没有粉色或橙色。
2. **生命周期与滑行**：12 帧位移结束后仍能看到 6 帧滑行拖尾；残影在 12 帧（滑行点 8 帧）内归零，不出现突然硬切，也不超过 9 个同时残影。
3. **满屏可读性**：在黄绿弹幕密集画面中连续冲刺，冲刺层仍只出现红/白/灰，中心白色判定点可见；粒子总量不超过 260，低配模式下每帧新增不超过 2 个。

## 9. 与现有网页端的对照备注

网页端当前已实现：`dashSpeed=1020`、`dashFrames=12`、`dashIFrames=16`、`dashRampFrames=3`、`dashOutFrames=6`、`dashOutKeep=0.72`；`game.js` 每 2 帧记录残影，`render.js` 以红色菱形和 `life/max` alpha 绘制。`fx.js` 已用 `lighter` 绘制球形态粒子，并以 `260` 作为粒子上限。本方案的速度线、专用拖尾和屏幕层是对现有残影/起步 burst 的设计补充，不代表本次已修改这些代码。
