## 1. 这是个什么项目

| 项目 | 内容 |
| --- | --- |
| 名称 | 《镜》（开发代号 MIRROR） |
| 场合 | CODEJAM 2026 游戏创作挑战（苏州大学计算机爱好者协会），限时 45 小时 |
| 类型 | 横版弹幕闪避（boss rush），单人 |
| 技术形态 | **网页游戏**：HTML5 Canvas + 原生 JavaScript，零依赖、零构建 |
| 素材形态 | 全部以 **PNG 图片**加载，由代码叠加、旋转、缩放、调色 |
| 题目 | 「镜」——作品必须能说明与题目的关联 |
| 硬约束 | 全画面**只能出现 3 个色相 + 黑白灰** |

**核心玩法一句话**：你只有三次机会，靠冲刺的无敌帧和可以随时变成的"光球形态"穿过满屏弹幕，把 BOSS 打出三个阶段。

### 玩法机制（美术需要知道的）

| 机制 | 表现需求 |
| --- | --- |
| 生命次数制 | 被打中三次直接重来，不做血条，所以受击反馈必须极强 |
| 冲刺 | 12 帧位移 + 16 帧无敌，需要冲刺残影表现 |
| **光球形态** | 空中长按冲刺变成球，持续无敌、全屏飞、消耗体力、落地取消。红白渐变，是本作最标志的视觉 |
| 擦弹连击 | 贴着弹幕擦过会累积连击、涨能量、返还冲刺冷却。需要"贴身擦过"的即时反馈 |
| 镜像弹幕 | BOSS 有一个以画面垂直中轴为对称的镜像分身，弹幕成对发射 |
| 三阶段 | 血量过阈值换阶段，换阶段清屏并给玩家一口气 |

## 2. 世界观与角色

童话人物群像，剧情由制作人负责，美术只需要知道"谁是谁、什么阵营"。

| 角色 | 定位 |
| --- | --- |
| 小红帽 蕾克 | 主角 |
| 白之兔 诺登 | 友方·引路人（开场剧情） |
| 虚空少女 梅贝尔 | 特殊 |
| 幕后黑手 玛丽苏 | 最终 BOSS |
| 猩红魔姬 蕾克 | 中段 BOSS，蕾克的暴走形态，**与主角同一剪影**，只差颜色与明度 |

> **登场角色最终 5 个**：蕾克、猩红魔姬蕾克、玛丽苏、白之兔诺登、梅贝尔。
> 其余角色（青蛙姬、白雪姬、长发姬、人鱼姬）因工期原因不登场。

**剧情中的关键视觉事件**：蕾克在故事中途受影响变成青色（剧情演出，不影响战斗），一切结束后恢复红色。所以同一个角色会有**三套配色素材**：

1. `rek` — 红（战斗中的常规形态）
2. `rek_cyan` — 青（剧情·被影响）
3. `rek_crimson` — 红·暗档（猩红魔姬，暴走形态）

三套**必须共用同一份线稿**，形状像素级一致，只有配色不同。

## 3. 色彩语义（2026-10 确认版，长期有效）

| 色相 | 色值 | 语义 | 谁用 |
| --- | --- | --- | --- |
| 红 | `#FF0000` | **我方** | 蕾克、友方角色、玩家的射击与擦弹反馈 |
| 绿 | `#82FF00` | **危险** | 一切弹幕、致命机关 |
| 青 | `#00BAFF` | **环境与中立** | 镜面、冰、湖、反射、中立角色 |
| 中性灰 | R=G=B | **结构** | 背景、场景、UI、文字、阴影 |

### 为什么危险色是绿的，不是红的

红色给了主角（小红帽的符号意义优先）。弹幕必须用一种"绝不属于玩家"的颜色，否则玩家在密集弹幕里会找不到自己。

绿色被选中是因为它是三个色里**最亮的**（人眼对 555nm 附近最敏感），在深色背景上辨识度最高。代价是绿色在游戏惯例里常代表"安全/治疗"，所以弹幕要用**锐利的几何形状**，并且游戏开局有教学。

### 角色色相与明度分配

| 角色 ID | 色相 | 明度档 | 说明 |
| --- | --- | --- | --- |
| `rek` | 红 | 0.62 | 主角，战斗形态 |
| `rek_crimson` | 红 | 0.34 | 同剪影，暗一档 |
| `norden` | 红 | 0.80 | 友方，最亮 |
| `mermaid` | 红 | 0.45 | 友方 |
| `marysue` | 青 | 0.30 | 反派，冷 |
| `frog` | 青 | 0.62 | 中立 |
| `hair` | 青 | 0.78 | 中立 |
| `rek_cyan` | 青 | 0.58 | 剧情·被影响 |
| `snow` | 灰 | 0.90 | 近白 |
| `mabel` | 灰 | 0.12 | 近黑 |

**同色相内靠明度档区分角色**，绝不靠新增颜色。并排放在一起要能一眼分清。

## 4. 视觉基调

- 极简、几何、高对比。参考气质：冷、干净、略带不安。
- 大量留白与中性灰背景，让三种颜色成为唯一的信息源。
- **镜像对称**是全局视觉母题：画面中轴、弹幕对称、BOSS 与它的镜像分身。
- 不做厚涂、不做复杂光影。形状优先于质感。

## 5. 协作约定（长期）

以后的每次任务都会包含这五项，请按顺序核对：

1. **目标**：要产出什么（改色 / 新角色 / 新动作 / UI / 背景）
2. **输入**：源文件在哪、什么规格
3. **输出规格**：尺寸、格式、透明通道、锚点、命名
4. **红线**：不许做什么（通常是：不许改形状、不许加颜色、不许加文字）
5. **验收**：怎么算通过

### 长期有效的硬规则

- **颜色永远只有那三个色相 + 中性灰。** 新任务、新角色、新 UI，一律不得引入第四种颜色。
- **"看起来像灰"不等于灰。** 偏蓝的深灰（`#222D39`，211°）、棕色（30°）、藏青（240°）都会违规。灰必须是 R=G=B。
- **改色 ≠ 重画。** 已有三视图的任务，只许改颜色，线条、比例、姿势、细节一个像素都不许动。
- **不要参考任何现成游戏的素材**，尤其《东方冰之勇者记》与东方 Project。我们只参考玩法机制，美术必须原创。
- **命名规则**：`<类型>_<角色ID>_<状态>.png`，例如 `char_rek_idle.png`、`view_rek_front.png`、`portrait_rek_calm.png`。
- **不要在图里写文字**（中文由代码渲染），不要烘焙落地阴影（代码会画）。

### 可用的自检工具

- `tools/check_palette.py`：逐像素检查色相是否越界，越界超过 1% 判不通过。
- `tools/recolor.py`：确定性改色，保留 alpha 与明暗层级，只替换色相。同一份线稿跑三次可得到三套配色且形状完全一致。
